## 二、数据来源与原始结构

| 文件 | 内容 |
|---|---|
| `guangzhou_bus_routes.shp/dbf` | 线路记录（含线路名、起讫、里程、票价、首末班、运营公司、几何） |
| `guangzhou_bus_stops.shp/dbf` | 站点（站点ID、站名、坐标、经过线路数） |
| `guangzhou_bus_segments.shp/dbf` | 线路分段 |
| `web_data/`、`data/*.js` | 预处理后的网站数据（GeoJSON/JS） |

原始字段要点（解析后）：
- 线路 `route_cn`：如 `655路(三达路跨线桥首末站--大塘汽车客运站)`，**线路号与起讫都写在名称里**；
- 站点 ID **不区分上下行**，同一站的两个方向平台可能是不同 ID（如 林和西路 vs 林和西路2），也可能是同一 ID；
- 部分站名带"2/3"数字后缀、`BRT` 前缀、`(北行)` 方向后缀、`(潭村)` 括号说明等——这些都是**分站/平台信息**，不是独立站名。

## 三、已知数据问题清单（踩过的坑）

### 3.1 同号不同线（最重要）

- **现象**：两条完全不同的线路共用同一个线路号。已确认 8 组：
  `655路`（佛山三水 vs 广州）、`312路`、`番19路`、`番52路`、`花1路`、`南沙61路短线`、`广州-肇庆`、`花81路`（三水大塘⇄广州北站 主线 vs 珊瑚⇄赤坭 短线）。
- **例子**：佛山三水 655（三达路跨线桥首末站 ⇄ 大塘汽车客运站，63 站）与广州 655（良田保税路总站 ⇄ 广东青年职业学院总站，23 站）都叫"655路"。
- **后果**：按线路号统计会把两条并成一条，共线/重复度/搜索全部出错。
- **处理**：见 4.3 线路身份聚类。

### 3.2 数字分站

- **现象**：`员村东2`、`白兔村路口1/2`、`嘉鸿花园站2` 等，站名末尾带数字，代表同一站的不同平台。
- **规模**：384 个数字结尾站名，全部能配对到基名；92 组有 2 个以上分站。
- **曾踩的坑**：`嘉鸿花园站2` 去掉数字是"嘉鸿花园站"（不是基名），基名其实是"嘉鸿花园"——中间隔个"站"字导致合并链条断裂，曾漏掉 27 个。

### 3.3 BRT 平台子站

- **现象**：`BRT岗顶N1`、`棠东站S1子站(BRT)`、`乌冲站S1子站(BRT)` 等，带 `BRT` 前缀或 `N1/S1/S2/子站` 后缀。
- **规模**：14 个含 BRT 字样、12 个带平台后缀。
- **坑**：这些平台子站的 ID 不在 B1 停靠表里，曾导致没有 BRT 标签；且与纯名站（岗顶）分裂成两个站。
- **坑**：`公共汽车BRT中山大道东圃站` 带"公共汽车"站牌前缀，原规则只去 `BRT` 前缀、不去"公共汽车"，导致同一 BRT 站被拆成 `中山大道东圃` / `公共汽车BRT中山大道东圃` / `公共汽车中山大道东圃` 三个站（B20 等线路两方向显示为不同站）。已修复：规范化时先去掉"公共汽车"前缀（全库仅 3 个此前缀站，均在同一站 100 米内）；当前合并站数 9212。

### 3.4 方向后缀

- **现象**：`松北(北行)`、`松北(停北行)`、`松北(南行)`——有些线路的**一个方向**会同时停靠该站两个方向平台，靠后缀区分。
- **规模**：119 个站名、63 组基名。
- **坑**：`同和(停北行)2` 这类"方向后缀+数字"的站名，别名构建时原正则要求方向后缀在名字**末尾**，数字 `2` 使其未被识别为方向后缀，被当成普通括号变体映射到纯名"同和"，导致 804 等 27 条停"同和"的线路全部错显示为"同和(停北行)"。已修复：方向后缀正则允许后带数字（`(停北行)\d*$`）。
- **环线规则**：方向后缀只用于**非环线**（如 B3 松北(北行)/(南行)，一个方向同时停双平台）；**环线**（188/792/731 等）绕圈会自然经过两个方向平台，停靠列表不显示后缀（显示纯名，绕回再次停靠仍保留，如 792 显示两个"同和"）。站点级规范名一律不带后缀（广医二院(停东行) → 广医二院）。

### 3.5 括号变体（同名不同写法）

- **现象**：`华侨医院` 与 `华侨医院(潭村)` 是同一站（相距 18 米）；但 `开泰大道(开达路口)` 与 `开泰大道(科丰路口)` 相距 1.7 公里，是不同站。
- **规模**：568 组括号基名；其中 521 组组内全部 ≤300 米（可合并）；147 组"纯名→括号名"完成合并。
- **坑**：`中山纪念堂(市总工会)3` 因末尾数字曾没归入"中山纪念堂"组，导致纯名错并给"中山纪念堂(连新路)"。
- **坑**：纯名只以"带站字"形式存在时（`东风东路站`，纯名"东风东路"本身不是站点），原分组逻辑把它分到单独一组，导致与 `东风东路(广东工大)`（相距约 90 米）不合并、204 路 A/B 方向显示为两个站。已修复：分组时先去掉末尾"站"字再归组；合并站数 9259 → 9214。
- **坑**：带数字后缀的站名（`中山纪念堂4`、`新丰路口2`）在规范时绕过括号别名，落到纯名站，而纯名本身被别名到括号站（如 中山纪念堂 → 中山纪念堂(市总工会)），导致同一物理站被拆成两个键、自动修复平台后线路"跨站"。已修复：规范顺序改为"去数字 → 套别名 → 再清理"，数字分站继承纯名的站归属；9 个站名归位（合并站数 9212 → 9205）。

### 3.6 "站"字变体与"分站"字样

- `程界村站` vs `程界村`：1913 组，已全部合并。
- `中山八路站2号分站`、`锦绣香江(分站)` 等文字型分站：28 个，已全部合并。
- **字母分站**：`雅居乐花园A站`、`新塘牛仔城A站`、`地铁汉溪长隆A/B/C/D/G站` 等"单字母+站"后缀并入基名（分析口径，显示保留字母）；`中国软件CBD站` 因字母前是字母不拆（CBD 是单词）。
- **总站写法**：`番禺宝墨园`、`宝墨园` 与 `宝墨园总站` 为同一总站（相距 ≤15 米），规范名统一为 `宝墨园总站`。

### 3.7 平台坐标与线路几何不一致

- **现象**：线路停靠记录里写的平台 ID 与线路几何实际经过的平台不一致。
- **例子**：`林和西路`(BV11688381) 距 363 线路几何 133 米，而 `林和西路2`(BV09383025) 距几何仅 2 米——363 实际停靠北侧平台；`299`、`B15` 存在双向平台记录颠倒。
- **教训**：**站点标记应按线路实际平台定位**（按几何挑最近平台），不要强行吸附到线、也不要钉死主站坐标。

### 3.15 方向分台（同站双方向停靠点分离）

- **现象**：部分站点的两个方向停靠点相距很远（如 566路 云埔工业区：南行各线路几何汇聚在距北行平台约 290 米处），数据只记录了一个方向平台，另一方向停靠点缺失；或记录指错了方向平台。
- **证据**：逐方向计算"记录平台→本方向线路几何"最近点，聚类后发现 129 处候选（剔除明显异站邻近后保留 87）；其中约 73 处为"真缺平台"（远侧汇聚点 100 米内无平台），其余为"换台候选"。
- **换台安全规则**（防止复刻 263路 林和西问题）：逐方向记录校验——记录平台距本方向几何 100–300 米、同族平台距本方向几何 ≤50 米才建议换台；**首末站不做换台**（终点站几何未延伸进站场属正常）；记录偏差 >300 米多为线路几何坏点，不换台。
- **补台方法**：用远侧各线路几何的汇聚点作为缺失方向站台的派生坐标（独立文件存放，不进原始分站数据）。
- **产出**：`派生方向站台候选_换台.csv`（195 条）、`派生方向站台候选_补台.csv`（73 条）。
- **换台落地（2026-08-16）**：按逐方向几何校验 + 规范化后**同一站**（norm 键相等）双重约束，落地 **56 条**同站换台（如 363 林和西路→林和西路2、西塱→西塱1/2）；**117 条跨站候选**（如 黄阁大道中站→黄阁医院站，线路实际停靠另一命名站）与 **22 条总站型目标**（如 太和文化广场→太和总站(沙亭岗村)）**不自动改，留人工确认**（涉及线路跨站归属，需按实况核实）。
- **补台落地（派生平台层）**：`data/derived_platforms.js`（73 条）记录远侧汇聚点坐标（独立于原始分站数据）；显示层 `bestStopPos` 兜底——站内平台距线路 >100m 且派生点 ≤150m 时，标记落在派生点（如 566 南行 云埔工业区）。
- **事故与恢复**：首轮换台按"目标 ID"批量撤回时，若目标平台原本就存在于该方向记录（如 南沙49 原 25 位即黄阁医院站），会把原本正确的记录一并改错；已从 `web_data/bus_route_stops.json`（原始数据）重建，重新应用 佛314 去重 + 高置信平台修正 + 同站换台，验证恢复至 合并站 9199 / 共线对 10983 / 走廊 1676，与换台前一致。

### 3.8 通用站名污染

- `临时站` 对应 **88 个不同站点ID**、`招呼站` 对应 **37 个**，同名不代表同站。
- **已修复**：通用站名按**站点ID区分**、不按名合并（含数字/括号变体），不再产生伪枢纽（修复后 体育中心 以 49 条线成为第一枢纽）。

### 3.9 疑似重复录入 / 命名变体

- `从13路` 与 `从化13路` 起讫基本相同（从化汽车站—白水寨，重叠 98%），已确认为改名重复，**已合并**（同一线路身份）。
- 同样确认并合并：`佛里07路`↔`里07路`（起讫/停靠 100% 重叠）。
- `南68路快线` 与 `南沙68路` 曾一度按别名合并，后确认番禺/南沙公交确有"正线/快线/短线"之分（南沙68 正线与快线是不同服务），**已撤销该别名**，两者保留为不同线路。
- 其余候选（日班×夜班、短线/长线/A线/B线/内环/外环等）一律不合并，完整排查结果见 `疑似重复与变体线路.csv`（见 3.13）。
- `314路` 与 `佛314路(周六)`（91%/93% 重叠）经站点比对确认为**日常正线 vs 周六绕行班次**（周六线经三善村口、多停新翁祐中学），不合并。

### 3.10 站名截断

- 已修复 3 个截断站名：`广州火车→广州火车站`、`从化客运→从化客运站`、`天河客运→天河客运站`（显示、搜索、拼音同步生效）。
- 若后续发现其他截断站名，在 `STOP_NAME_FIXES` 中追加即可。

### 3.11 环线重复站

- **现象**：单向环线（起讫相同，如 `996路(水秀二路总站--水秀二路总站)`、`188路(大基头总站--大基头总站)`）绕行一圈会**再次停靠同一站**（996 的水秀二路总站/水秀二路/芳村车管所各出现 2 次）。
- **规模**：185 条环线方向记录全部含重复站。
- **曾踩的坑**：为处理"员村东/员村东2"这类分站变体而做的显示去重，把环线里"绕回来再停一次"的重复站也吃掉了。
- **处理**：环线方向只去掉**连续重复**（数据错误），保留绕行再次停靠的站；普通线路维持原有去重。
- **坑**：起讫提取最初用正则无法处理站名自带括号的环线（如 `290路(金沙洲(涛乐街)总站--金沙洲(涛乐街)总站)`），被误判为普通线导致回程站被去重吃掉；已改为"按括号配对取最后一个 `--` 所在块"的解析，`花81路(广州北站(秀全大道)--三水大塘中心广场总站)` 这类括号站名也能正确提取。

### 3.12 停靠记录与线路几何不一致

- **现象**：线路停靠记录里的平台坐标与线路几何相距较远（363 林和西路 133 米、299/B15 双向平台颠倒等）。
- **产出**：`停靠记录几何不一致清单.csv`（426 条 ≥150 米，其中 108 条给出"同一合并站内离几何最近的平台"作为建议）。
- **已自动修复 105 条**（2026-08-16）：85 条（150–300 米档 + 建议平台 ≤50 米）+ 20 条（300–1000 米档、完整分站口径下同站平台 ≤50 米，如 赤岗→赤岗(江海大道)站、江南新村→江南新村(骨伤科医院)）；其余 321 条留人工核对（含 138 条首末站偏差大概率无需改、20 条整线几何异常如 花81路/944路）。
- **口径同步**：清单生成脚本已改用与 `make_network_analysis.js` 完全一致的分站分组（含括号别名、公共汽车前缀、数字分站继承别名等），并新增"是否首末站/站名含总站/偏差档位/核对提示"四列，可直接按提示筛选分拣。
- **注意**：清单里含 3–6 公里的大偏差条目（如 花81路、944路），多为线路几何缺段/指向异常，需人工逐个核实，建议优先处理 150–300 米档。

### 3.13 疑似重复 / 变体线路候选（全网排查）

检测条件：不同线路号、起讫相近（任一端 ≤300 米）、停靠重叠 ≥ 较短线的 80%。结果共 **120 对**（`疑似重复与变体线路.csv`）：

- **正线-变体 92 对（不合并）**：带运营标记、确为不同服务。包括 快线（南68快线×南沙68、番28B×番28B快线）、短线（番93×番93短线、花68×花68短线）、夜班（564×夜100、978×夜63、924×夜62）、高峰（番125高峰直达短线）、环线/内环/外环（456×456环线、增城32内环×外环）、上午/下午（新龙镇02线）等；
- **跨区或同走廊 24 对（不合并）**：不同线路号、真正不同的线路（南沙65×番142、551×59、从14×从19、430×长洲岛1号线 等）；
- **疑似改名 3 对（4 条记录）**：`从13×从化13`（98%，已合并）、`佛里07×里07`（100%，已合并）、`314×佛314(周六)`（91%/93%，经站点比对确认为**日常正线 vs 周六绕行班次**：周六线经三善村口、多停新翁祐中学，不合并）。

> 原则：**带快线/短线/长线/夜班/环线等运营标记的，一律视为不同服务，不自动合并**；只有"无运营标记 + 仅地理前缀差异 + 重叠≈100%"才考虑改名合并，且需人工确认。

### 3.14 站名更名变体（学校更名）

- **现象**：`顺德一中实验学校`（BV10253902）与 `广东顺德文德学校`（BV09227917）坐标完全相同（113.263445, 22.855668），是学校更名导致的站名新旧写法；314路去程/佛314路仍用旧名，314路返程已用新名。
- **处理**：经确认以**新名 `广东顺德文德学校` 为规范名**，加入 `STOP_NAME_FIXES`（旧名可继续搜索，显示/分析统一用新名）；两个平台 ID 合并为同一站。

## 四、当前治理规则（当前版本，可能调整）

### 4.1 站名规范化管道

按以下顺序处理一个原始站名（`normStopName` / `displayStopName`）：

1. **去掉标记**：`BRT` 前缀、`(BRT)` 后缀、平台后缀（`N1/S1/S2`、`子站`）、`N号分站`、`分站`、`(分站)`；
2. **数字分站**：末尾数字去掉，基名按 `基名 → 去站 → 加站` 试探（带括号的数字变体保留括号）；
3. **括号变体别名**（仅显示/身份层）：纯名 ↔ 括号名、坐标 ≤300 米才合并；
4. **方向后缀**：`(北行)/(停北行)/(南行)` 等并入纯名（分析口径）；
5. **"站"字**：基名存在时去掉。

> 注意：`displayStopName`（用于停靠站点列表显示）保留方向后缀，`normStopName`（用于共线等分析）去掉方向后缀——两条管道口径不同是**有意为之**。

### 4.2 括号变体合并规则（当前版本）

- 只有"一个有括号、一个没有括号"的组合才考虑合并；
- 仍要求坐标距离 ≤300 米（`华侨医院` ↔ `华侨医院(潭村)` 18 米 → 合并）；
- 两个都带括号、内容不同（`开泰大道(开达路口)/(科丰路口)`）→ **一律不合并**；
- 方向后缀括号（`(东行)` 等）不参与该规则。
- "纯名"包括带"站"字的写法：`东风东路站` ↔ `东风东路(广东工大)`（90 米）→ 合并，规范名取括号版本；`东风东路(陵园西路口)` 相距约 2 公里 → 不合并。

### 4.3 线路身份（同号不同线）

- 规则：同一线路号下，按**起讫坐标聚类**（两个方向记录若起讫任一端 ≤300 米则同线）；
- 佛山/广州 655 起讫相距极远 → 自动拆成两条；
- 全库 161 组"同号不同起讫"中，154 组是站名写法差异（景泰坑总站 vs 景泰坑临时总站）被正确合并，8 组真不同线被拆分；
- 线路身份 key 形如 `655路#0`、`655路#1`。

### 4.4 平台附属数据（保留未来切换余地）

- 每个合并站下挂全部分站：`stationPlatforms[合并站] = [{原始站名, 站点ID, 经度, 纬度}]`；
- 导出文件：`分站规范化字典.csv`；
- 用途：未来若拿到可靠的站台级数据、想切回"分站分开显示/分析"，可直接基于此还原，无需重新整理。

### 4.5 拼音索引

- `data/stop_pinyin.js`：10054 个站名的首字母缩写 + 全拼（`员村东 → ycd / yuancundong`）；
- 生成脚本：`make_stop_pinyin.py`（依赖 pypinyin）。

### 4.6 站名修正表（当前版本）

`STOP_NAME_FIXES`：截断/更名站名修正，作用于显示、搜索、拼音（如 `广州火车 → 广州火车站`、`顺德一中实验学校 → 广东顺德文德学校`）。旧名在搜索中保留为别名，显示统一用新名。

### 4.7 通用站名规则（当前版本）

`临时站`/`招呼站` 开头（含 `临时站1`、`临时站(XX)` 等变体）一律**按站点ID区分**：不参与括号别名、不按名聚合、共线只按本站ID匹配。

### 4.8 线路别名（当前版本）

`ROUTE_ALIASES`：改名/重复录入的同一线路（`从13路 → 从化13路`、`佛里07路 → 里07路`），在"线路身份"计算前归一，网站与分析共用。带运营标记（快线/短线/夜班等）的一律不设别名。

### 4.9 线网图结构（data/network_graph.js）

| 字段 | 含义 |
|---|---|
| `nodes` | 分站节点 `[站点ID, 站名, 经度, 纬度]` |
| `nodeIndex` | 站点ID → 节点索引 |
| `keys` / `keyLabels` | 线路身份（含同号不同线拆分）/ 可读标签 |
| `dirs` | 方向记录（完整线路名） |
| `routes` | 每条方向记录的站序（节点索引序列） |
| `edges` | 乘车边 `[起点, 终点, 线路身份索引, 方向索引]` |

## 五、设计原则

1. **按坐标距离辨别，不按名称臆断**：名称差异（括号、站字、数字）是否同站，一律用坐标说话。
2. **保守合并**：只有基名确实存在（或能推断）才合并，避免误伤正规站名（如 `员村总站` 不会被拆成"员村总"）。
3. **分析用合并站、定位用真实平台**：共线/重复度按"站"算，但地图标记放到线路实际停靠的平台坐标。
4. **规则可逆、数据可还原**：所有合并都建立在原始分站数据之上（`network_graph.js`、`分站规范化字典.csv`），随时可以回到平台级口径。
5. **两条口径分开**：显示保留细节（方向后缀、括号），分析统一到站级——避免"为了显示牺牲分析"或反过来。
